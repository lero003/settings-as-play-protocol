# SaPP の哲学

> 設定は、固定された正解でも、自由に使える素材でもない。
> それは、守ると決めた約束と、開いておく余白の組である。

English summary: A setting is a promise plus a space for play. SaPP makes both explicit so that sharing, derivation, and disagreement can be discussed precisely, without pretending that credit is permission, that public means reusable, or that canonical means good.

This is not legal advice. It is a note about the design and limits of the format.

## なぜ「哲学」を書くのか

マニフェストは、SaPP が何を大切にしているかを言葉にしている。
この文書は、その言葉がなぜ成り立つのか、どこまで主張してよいのか、どこで間違えやすいかを整理する。

形式は、正しさを保証しない。
けれど、何を守り、何を変えてよいかを言葉にすることで、すれ違いを「盗用か変奏か」の審判から、「どの約束を守り、何を変えたか」の会話に変えられる。

## 名前について：Play と Protocol

ここでいう **Play** は、ゲームに限らない。
設定を使って想像する、生成する、演じる、書く、描く、直す、誰かに渡す。
その一回ごとの試みを指す。

**Protocol** は、通信規格のような厳密な技術仕様ではない。
設定を共有し、派生し、継承するための、最小限の作法と記録形式のことだ。

SaPP は、Play の場所を作るのではなく、Play が別の場所でも続けられるようにする。

## 1. 問題：設定の共有は、二つの失敗に陥りやすい

設定を人に渡すとき、極端な二つの態度がある。

- **閉じる**: 少しでも変えたら別物。元の作者だけが正史を決める。共有は「見せる」だけで、受け渡しにはならない。
- **開く**: 何がその設定なのかを決めず、すべてを自由素材にする。名前と雰囲気だけが残り、派生は元との関係を失う。

現実の共有は、この間にある。だが、その間を言葉にする語彙が少ない。
プロンプト、口頭の説明、SNS の投稿、Wiki、チャットのログ。どれも設定を運べるが、何が約束で何が余白かは、受け取る側の推測に任されやすい。

AI は、その推測を埋めるのが得意だ。
しかし、埋めた内容が「元の設定に書かれていたこと」と誤認されると、共有は静かに壊れる。

## 2. 提案：約束と余白を分ける

SaPP の中心にあるのは、次の分離だ。

- **Core Rules**: その設定がその設定であり続けるために、著者が互換性の条件として宣言する制約。
- **Variables**: 変えてもその設定として認識できる、開かれた範囲。

これは、設定を二つの箱に分類する作業ではない。
**何を同じものとして扱うか** を、受け取る側と共有するための約束である。

この分離があると、派生はこう語れる。

> この Core Rule は残した。この Variable を変えた。だからこれは互換の派生である。
> この Core Rule を変えた。だからこれは別バージョンか、inspired-by である。

「盗用か変奏か」という道徳的な審判を、まず「何を変えたか」という観察可能な記述に開く。
もちろん、それで権利問題が消えるわけではない。けれど、少なくとも会話の出発点ができる。

## 3. Core Rules は「本質」ではない

ここは、SaPP がいちばん誤解されやすいところだ。

Core Rules は、設定の奥に隠れた客観的な本質ではない。
**著者が、この用途ではここを守ってほしいと宣言する互換性条件** である。

だから、同じ設定でも、用途が変われば Core Rules は変わりうる。
画像生成で守りたいことと、短編で守りたいことは同じではない。
カードに書かれた Core Rules は、そのカードが想定する用途に対する約束だ。
用途を変える派生では、Core Rules を引き継ぐか、新しいカードとして再宣言するかを選ぶ。
引き継がない場合は、互換の派生ではなく、別バージョンか inspired-by として扱う。

この立場は、相対主義ではない。
「何でもあり」でもない。
**決定を隠さない** という立場である。
誰が、どの用途のために、何を核としたのか。それをカードに書く。
書かれた以上、派生側はそれに対して「守った / 変えた / なぜ変えた」を返せる。

### 核と余白を分けるための四つの問い

1. **変更テスト**: それを変えると、この用途で「別の設定」になるか。
2. **認識テスト**: それを変えても、受け取る側は同じ設定だと認識できるか。
3. **約束テスト**: それを変えると、この設定が交わしている約束（トーン、安全境界、アイデンティティ）が壊れるか。
4. **スコープテスト**: それは設定全体の約束か、それとも一つの媒体・場面のための詳細か。

四つの答えは、しばしば一致しない。
一致しないときは、どれを優先したかを書く。それが、そのカードの立場になる。

「全部が Core」でもよい。ただしそれは、派生を歓迎しない閉じた設定だと明示する。
「ほとんどが Variable」でもよい。ただし、何が残ればその設定なのかは書く。
形式は、正解を決めない。決定を監査可能にする。

## 4. 三つの分離

SaPP は、三つの似ているが違うものを分ける。

| 分けるもの | よくある混同 | なぜ危ないか |
|---|---|---|
| 由来 ≠ 許諾 | クレジットを付ければ使ってよい | 出典表示が、利用許諾の代わりになる |
| 公開 ≠ 再利用可能 | 見えるものは自由に使える | 公開は、利用の許諾ではない |
| 正史 ≠ 良さ | canonical なら良い設定、derivative なら劣る | 権威と品質、公式性と創造性が混ざる |

この三つが崩れると、SaPP は「クレジットさえ付ければ何でもできる」「公開されているものは自由に使える」「canonical なら良い」という道具に誤読される。
それは、この形式が目指すものではない。

## 5. よくある失敗

### クレジット・ウォッシング

由来を書くことで、許諾のない利用を正当化してしまう。

**兆候**: 「出典は書いたから大丈夫」「リンクを貼ったから自由に使える」。

**対処**: 由来と許諾を別の欄に書く。許諾がない場合は、使わないか、問い合わせる。

### コア・ウォッシング

自分の好みをすべて Core Rules にし、派生を実質的に禁止する。

**兆候**: Core Rules が長く、変更のたびに「それは違う」となる。Variables が空に近い。

**対処**: Core Rules を「守らないと別物になるもの」に絞る。閉じたいなら、閉じた設定として明示する。それは悪いことではない。

### バリアブル・スプロール

すべてを Variables にし、何が共有されているのか分からなくする。

**兆候**: 「何でも自由」と書きながら、元の設定の名前だけが残る。

**対処**: 少なくとも一つは、変えたら別物になる線を引く。それが引けないなら、それは設定ではなくムードかもしれない。

### カノン・キャプチャー

派生や AI 生成物が、権利者の承認なく「公式」「正史」を名乗る。

**兆候**: Canonical Status が無い、または derivative なのに canonical と表示される。

**対処**: Canonical Status を明示する。AI 生成物は、明示がない限り non-canonical とする。

### プロトコル信仰

形式を整えれば、権利も倫理も解決すると信じてしまう。

**兆候**: 「SaPP に書いてあるから大丈夫」「Validator が通ったから安全」。

**対処**: 形式は対話の語彙であり、対話そのものではない。法、プラットフォーム、関係者の合意は別に確認する。

## 6. この形式が約束しないこと

- 法的な利用許諾
- 設定の品質や一貫性の保証
- コミュニティの合意形成
- AI がカードを常に正しく解釈すること
- 悪意ある文書に対する安全性
- 元の作者の承認

SaPP が提供できるのは、確認すべきことを減らすことではなく、**何を確認すべきかを見えるようにすること** だ。

## 7. それでも、なぜやるのか

設定は、次の誰かが遊び始めるための種になりうる。
派生は、元を消すことではなく、由来を残して別の遊びを開くことだ。
開くか閉じるかを選べること自体が、尊重の条件になる。

SaPP は、すべての設定を開放する運動ではない。
**開く設定と閉じる設定の、どちらもそのまま渡せるようにする** ための小さな形式である。

## 8. 一枚のカードが答える四つの問い

1. これは何か。 — Name / One-liner
2. 何を守るのか。 — Core Rules
3. 何を変えてよいのか。 — Variables
4. 誰の、どんな条件で、どこから来たのか。 — Derivation & Credit

この四つに答えられれば、カードは短くてもよい。
逆に、どれかが欠けると、受け取る側は推測で埋めるしかない。
SaPP は、その推測を減らすための形式である。

## 9. 人に説明するときの三文

1. SaPP は、設定を「固定された正解」でも「自由素材」でもなく、守る約束（Core Rules）と開く余白（Variables）に分ける小さな形式です。
2. 派生は、どの約束を守り、何を変えたかで語れるようになります。AI にも人間にも、同じ境界が見えるからです。
3. ただし、クレジットは許諾ではありません。カードごとの許諾、公開範囲、正史扱いを別に確認します。

この三文で伝わらない相手には、無理に全部を説明しなくてよい。
まず一枚のカードを一緒に書いてみる方が早い。
